# Java 线程安全

记于 2026.11.25

多线程同时读写同一份数据，结果取决于线程的执行顺序，就是线程安全问题。两个线程同时对同一个变量自增，自增是读、加、写三步，交错执行会丢更新。

## synchronized：互斥锁

两种用法：

```java
// 同步代码块：锁任意对象
synchronized (锁对象) {
    count++;
}

// 同步方法：锁的是 this（静态方法锁的是 Class 对象）
public synchronized void add() {
    count++;
}
```

规则：多个线程必须用**同一把锁**才能互斥——锁对象不一样，synchronized 等于没加。锁对象选共享资源本身或专门的锁对象，不能每次 new 一个。

修饰 static 方法时锁的是 `类名.class`，它和锁 this 是两把不同的锁，二者之间不互斥。

synchronized 是可重入的：同一个线程可以重复获取自己已持有的锁，不会把自己锁死。

## Lock：显式锁

java.util.concurrent.locks.ReentrantLock，功能与 synchronized 相同，额外提供尝试加锁、超时加锁、公平锁：

```java
private final Lock lock = new ReentrantLock();

public void add() {
    lock.lock();
    try {
        count++;
    } finally {
        lock.unlock();      // 必须在 finally 里解锁
    }
}
```

与 synchronized 的差别：

- `tryLock()`：拿不到锁立即返回 false，不阻塞
- `tryLock(超时, 单位)`：限时等待
- `lockInterruptibly()`：等待锁的过程中可被中断
- 构造器传 true 得到公平锁（先到先得，吞吐量低）

unlock 必须写在 finally 里，漏掉解锁比 synchronized 更危险——synchronized 出异常自动释放，Lock 不会。

## 死锁

两个线程各自持有自己的锁，同时等待对方释放，永远等下去：

```java
// 线程1：先锁 A 再锁 B；线程2：先锁 B 再锁 A —— 互相等待
```

产生死锁的四个条件：互斥、持有并等待、不可剥夺、循环等待。破坏任意一个即可避免，方法是所有线程按相同的顺序获取锁。tryLock 超时获取失败就放弃，也能避免死锁。

排查：`jconsole` 或 `jstack 进程id` 能直接打印出"Found one Java-level deadlock"。

## 线程通信：wait / notify

Object 类的方法，必须在 synchronized 块里调用，否则抛 IllegalMonitorStateException。锁对象上的 wait/notify 配套使用：

- **wait()**：释放锁并进入等待，直到被 notify 唤醒后重新抢锁
- **notify()**：随机唤醒该锁对象上等待的一个线程
- **notifyAll()**：唤醒所有等待线程

wait 要放在 while 里判断条件，不能放 if——被唤醒时条件可能又被别的线程改掉了：

```java
synchronized (queue) {
    while (queue.isEmpty()) {     // while 不是 if
        queue.wait();
    }
    Object item = queue.poll();
}
```

生产者-消费者：队列空时消费者 wait，队列满时生产者 wait，存取后 notifyAll 唤醒对方。

sleep 和 wait 的区别：sleep 是 Thread 的静态方法，抱着锁睡，不释放锁；wait 是锁对象的方法，释放锁。
