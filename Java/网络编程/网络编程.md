# Java 网络编程

记于 2026.11.25

TCP 面向连接、可靠传输，UDP 无连接、不保证送达。TCP 用于文件传输、HTTP；UDP 用于视频流、心跳包这类丢一两包无影响的场景。

## TCP：Socket 通信

服务端用 ServerSocket 监听端口，accept() 阻塞等待连接，返回 Socket；客户端用 Socket 直接连。双方各拿到一个 Socket 后，通过 getInputStream / getOutputStream 收发字节：

```java
// 服务端：accept 阻塞等连接，一个连接一个线程处理
ServerSocket server = new ServerSocket(18080);
while (true) {
    Socket socket = server.accept();     // 阻塞点
    new Thread(() -> 处理(socket)).start();
}

// 客户端
Socket socket = new Socket("127.0.0.1", 18080);
OutputStream out = socket.getOutputStream();
out.write("你好".getBytes());
socket.shutdownOutput();     // 关闭输出方向，告诉对方发完了
```

read() 是阻塞的，对方不写数据就一直等。**双方必须约定消息边界**，否则 read 分不清"消息到哪结束"：

- 约定结束标记（如一行一行读，用 BufferedReader 的 readLine）
- 约定先发长度再发内容
- `socket.shutdownOutput()` 单向关闭，配合对方读到 -1

读取时用 `read(byte[])` 的返回值判断读了多少字节，-1 表示对端关闭了输出流。TCP 粘包：多次 write 的小包可能被合成一次 read 收到，靠消息边界解决。

## UDP：DatagramSocket

无连接，直接对目标地址发包，每次收发一个 DatagramPacket（自带对方地址）：

```java
// 发送方
DatagramSocket ds = new DatagramSocket();
byte[] data = "你好".getBytes();
DatagramPacket packet = new DatagramPacket(data, data.length,
        InetAddress.getByName("127.0.0.1"), 18081);
ds.send(packet);
ds.close();

// 接收方
DatagramSocket ds = new DatagramSocket(18081);   // 绑定端口
byte[] buf = new byte[1024];
DatagramPacket packet = new DatagramPacket(buf, buf.length);
ds.receive(packet);                              // 阻塞等包
String msg = new String(packet.getData(), 0, packet.getLength());
```

- 包大小受 UDP 报文限制，数据在 64KB 以内，实际建议不超过 1KB
- send 不等待确认，丢了就是丢了
- receive 收到的 packet 里带发送方地址：`packet.getAddress()`、`packet.getPort()`，回包用这个地址

## 端口与地址

- `InetAddress.getByName("主机名或IP")` 解析地址；`getLocalHost()` 取本机
- 0~1023 是系统保留端口，测试用 10000 以上；端口被占用抛 BindException
- 一个端口同一时刻只能被一个进程绑定；ServerSocket 不 close 就释放不了

## 两个常见错误

**Connection refused**：目标端口没人监听，或服务端没 start。**BindException: Address already in use**：端口被占，换个端口或找到占用进程结束它。服务端 socket 不关闭时，重复绑定直接抛这个。
