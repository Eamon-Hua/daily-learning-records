# Java 异常

记于 2026.11.19

程序跑到一半出错就崩，异常就是给这个"崩"装一个缓冲垫：**能预料的接住处理，接不住的往上抛**。

## 异常体系

Throwable 下面两大类：

- **Error**：虚拟机级别的错，OutOfMemoryError、StackOverflowError 这类，程序管不了，不用管
- **Exception**：程序能处理的。又分两种：
  - 编译期异常（受检异常）：IOException、ClassNotFoundException，不处理编译都过不了
  - 运行期异常（RuntimeException 及其子类）：空指针、数组越界、类型转换，编译不拦，跑起来才炸

RuntimeException 是个分界线：它和它的子类都是不受检的，其他 Exception 都要 try 或者 throws 二选一。

## try-catch-finally

```java
try {
    int r = 10 / 0;              // 这里抛 ArithmeticException
} catch (ArithmeticException e) {
    System.out.println("算错了：" + e.getMessage());   // / by zero
} finally {
    System.out.println("无论如何都执行");
}
```

几个要点：

- catch 可以写多个，从上往下匹配，**子类异常要写在父类前面**，写反了编译报错（后面的 catch 永远轮不到）
- 想偷懒一个 catch 接多种异常：`catch (AException | BException e)`
- e.getMessage() 拿简短信息，e.printStackTrace() 打完整调用栈，排查问题用后者

finally 的执行时机要背下来：**try 或 catch 里就算 return 了，finally 也照样执行**。只有 System.exit() 这种直接杀虚拟机的才轮不到它。所以关资源、解锁这类"必须收尾"的活都放 finally。

一个容易错的点：finally 里也写 return 会把 try 里的返回值直接覆盖掉，别这么写。

## throw 和 throws

这俩长得像，完全是两回事：

- **throws** 写在方法签名上，是声明："这方法可能出这毛病，我不处理，谁调谁接"
- **throw** 写在方法体里，是动作：真的抛出一个异常对象出去

```java
public void 取钱(double money) throws 取款异常 {
    if (money > 余额) {
        throw new 取款异常("余额不足");    // throw 一个对象，后面代码不再执行
    }
}
```

throw 出去之后方法立即结束，这行后面的代码不跑。声明式的异常谁调用谁 catch，不 catch 就继续往上 throws，最顶端没人接就 JVM 崩掉打印栈。

## 自定义异常

继承 RuntimeException（想要不受检）或 Exception（想要强制处理）就行，写个构造器传 message：

```java
class 取款异常 extends RuntimeException {
    public 取款异常(String message) {
        super(message);          // 把信息传给父类，getMessage() 就能拿到
    }
}
```

什么时候自己写：JDK 自带的异常描述不了你的业务错的时候。余额不足、年龄不合法这种，抛 IllegalArgumentException 语义太糊，自定义一个名字一看就懂。
