# Java 抽象类与接口

记于 2026.11.18

这俩都是"只说不做"的设计：把规矩定下来，活儿让子类去干。

## 抽象类 abstract

父类里有些方法根本没法写实现——比如"图形"的"面积"，不同图形算法完全不同，写在父类里就是胡说。这种就声明成 abstract，**方法只有签名没有方法体**，类也得跟着 abstract：

```java
abstract class 图形 {
    abstract double 面积();     // 不写 {}，直接分号

    public void 描述() {        // 抽象类里也能有正常方法
        System.out.println("我的面积是" + 面积());
    }
}
```

规矩就三条：

- 抽象类不能 new，只能当爹
- 子类必须把所有抽象方法都重写掉，不重写子类自己也得标 abstract
- 抽象类可以有构造器（给子类 super() 用的）、可以有普通方法、可以有成员变量

一开始我老纠结"不能 new 那构造器有啥用"——有用，子类构造器第一行 super(...) 还是要调它。

## 接口 interface

接口比抽象类还极端：**全是规矩，没一丁点实现**（8.0 之前是这样）。

```java
interface 会飞 {
    void 飞();                  // 自动就是 public abstract，不用写

    default void 降落() {       // 默认方法，有实现体
        System.out.println("减速降落");
    }

    static void 限高() {        // 静态方法，接口名直接调
        System.out.println("飞行限高1000米");
    }
}
```

实现用 `implements`，一个类可以实现好几个接口（这是跟继承最大的区别——**类是单继承，接口能多实现**）：

```java
class 飞机 implements 会飞 {
    @Override
    public void 飞() {
        System.out.println("引擎推动");
    }
    // 降落() 不重写也行，用接口给的默认实现
}
```

## 默认方法是干嘛的

接口要加新方法时麻烦：加了所有实现类全得跟着改，老代码全崩。default 就是给这个口子的——**接口里带实现体，实现类可重写可不重写**。集合框架里 forEach 就是典型，Collection 加了 default 的方法，老集合类不用动。

## 俩咋选

我的理解：

- **是不是同类** → 抽象类。"猫是一种动物"，用 extends，天生就那一个爹
- **有没有额外能力** → 接口。"鸟会飞、飞机也会飞、超人也会飞"，会飞不是一个物种，是一个技能包，就做成接口让人 implements

所以抽象类回答"是什么"，接口回答"能干什么"。
