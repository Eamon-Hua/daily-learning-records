# Java 继承

记于 2026.11.18

继承就一个词：**儿子不用重写爹的东西**。公共的属性方法抽到父类里，子类 `extends` 一下全有了。

## extends

```java
class 动物 {
    String 名字;

    public void 吃() {
        System.out.println(名字 + "在吃东西");
    }
}

class 狗 extends 动物 {   // 狗什么都没写，也有了 名字 和 吃()
}

public static void main(String[] args) {
    狗 d = new 狗();
    d.名字 = "旺财";
    d.吃();          // 旺财在吃东西，方法是从爹那继承来的
}
```

Java 只能单继承，一个类只能有一个亲爹。但爹上面还有爷爷，一层层下去叫多层继承。

## super

`super` 就是"找我爹的"。三个用法：

```java
class 动物 {
    public 动物(String 名字) {
        System.out.println("动物构造器");
    }

    public void 吃() {
        System.out.println("吃东西");
    }
}

class 猫 extends 动物 {
    public 猫(String 名字) {
        super(名字);        // 1. 调爹的构造器，必须是子类构造器第一行
    }

    @Override
    public void 吃() {
        super.吃();         // 2. 调爹被重写前的版本
        System.out.println("猫还要吃鱼");
    }

    public void 测试() {
        System.out.println(super.名字 == null);   // 3. super.属性，实际很少这么用
    }
}
```

第一行的规矩跟 `this(...)` 一样，所以构造器里 `super(...)` 和 `this(...)` 只能挑一个写。不写的话编译器偷偷塞一个无参的 `super()` 进去——**爹要是没写无参构造器，子类不写 super(参数) 就编译不过**，这个报错第一次见很懵，其实就是这个原因。

## 方法重写 @Override

子类觉得爹的方法不合口味，重新写一遍，方法签名必须一模一样（名字、参数，返回值类型小于等于爹的）：

```java
@Override
public void 吃() {   // 签名跟爹的完全一致
    ...
}
```

`@Override` 不写也能重写，但建议写上，两个好处：

- 写错了（比如方法名拼错、参数不同）编译器直接报错，等于帮你检查了一遍
- 别人一看就知道这是重写的，不是新方法

注意：**重写只看方法名和参数，访问权限只能放大不能缩小**——爹是 protected，子类重写只能 public 或 protected，不能改成 private。static 方法谈不上重写（那是隐藏）。

## 访问权限四个档

| 修饰符 | 自己类 | 同包 | 子类 | 任意地方 |
| :---: | :---: | :---: | :---: | :---: |
| private | ✓ | ✗ | ✗ | ✗ |
| 缺省（不写） | ✓ | ✓ | ✗ | ✗ |
| protected | ✓ | ✓ | ✓ | ✗ |
| public | ✓ | ✓ | ✓ | ✓ |

记法：private 是隐私，protected 是给儿子留的遗产，public 谁都能碰，什么都不写就是"同小区的随便进"。子类想用爹的东西，爹的属性方法至少得 protected 或同包。

## 调用顺序坑

new 子类对象，爹的构造器先跑：

```java
new 猫("咪咪");
// 输出：
// 动物构造器
```

所以别在父类构造器里调被子类重写的方法——那时候子类自己的属性还没初始化，方法跑了也白跑。
