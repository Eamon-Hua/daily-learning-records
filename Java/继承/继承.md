# Java 继承

记于 2026.11.18

继承：**子类直接获得父类的属性和方法**。公共的属性和方法抽到父类里，子类 `extends` 之后直接拥有。

## extends

```java
class 动物 {
    String 名字;

    public void 吃() {
        System.out.println(名字 + "在吃东西");
    }
}

class 狗 extends 动物 {   // 狗什么都没写，也有了 名字 和 吃()
}

public static void main(String[] args) {
    狗 d = new 狗();
    d.名字 = "旺财";
    d.吃();          // 旺财在吃东西，方法继承自动物
}
```

Java 只能单继承，一个类只有一个直接父类。父类上面还可以再有父类，层层往上叫多层继承。

## super

`super` 用于访问父类成员。三个用法：

```java
class 动物 {
    public 动物(String 名字) {
        System.out.println("动物构造器");
    }

    public void 吃() {
        System.out.println("吃东西");
    }
}

class 猫 extends 动物 {
    public 猫(String 名字) {
        super(名字);        // 1. 调父类构造器，必须是子类构造器第一行
    }

    @Override
    public void 吃() {
        super.吃();         // 2. 调父类被重写前的版本
        System.out.println("猫还要吃鱼");
    }

    public void 测试() {
        System.out.println(super.名字 == null);   // 3. super.属性，实际很少这么用
    }
}
```

第一行的规矩跟 `this(...)` 一样，所以构造器里 `super(...)` 和 `this(...)` 只能挑一个写。不写的话编译器会自动补一个无参的 `super()`——**父类要是没写无参构造器，子类不写 super(参数) 就编译不过**，这个报错第一次见容易看不懂，原因就是这个。

## 方法重写 @Override

子类要改变父类方法的行为时重新实现一遍，方法签名必须一模一样（名字、参数，返回值类型小于等于父类的）：

```java
@Override
public void 吃() {   // 签名跟父类的完全一致
    ...
}
```

`@Override` 不写也能重写，但建议写上，两个好处：

- 写错了（比如方法名拼错、参数不同）编译器直接报错，等于多一道检查
- 别人一看就知道这是重写的，不是新方法

注意：**重写只看方法名和参数，访问权限只能放大不能缩小**——父类是 protected，子类重写只能 public 或 protected，不能改成 private。static 方法谈不上重写（那是隐藏）。

## 访问权限四个级别

| 修饰符 | 自己类 | 同包 | 子类 | 任意地方 |
| :---: | :---: | :---: | :---: | :---: |
| private | ✓ | ✗ | ✗ | ✗ |
| 缺省（不写） | ✓ | ✓ | ✗ | ✗ |
| protected | ✓ | ✓ | ✓ | ✗ |
| public | ✓ | ✓ | ✓ | ✓ |

子类要用父类的成员，父类的属性方法至少得 protected 或同包可见。

## 调用顺序坑

new 子类对象，父类构造器先执行：

```java
new 猫("咪咪");
// 输出：
// 动物构造器
```

所以别在父类构造器里调被子类重写的方法——那时候子类自己的属性还没初始化，方法执行了也拿不到正确结果。
