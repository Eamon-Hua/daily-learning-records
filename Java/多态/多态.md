# Java 多态

记于 2026.11.18

多态：**父类引用指向子类对象，调用方法时实际执行的是子类的版本**。编译看左边，运行看右边。

## 向上转型

```java
动物 a = new 狗();    // 狗的对象交给动物类型的引用，这就是向上转型
a.吃();              // 跑的是狗重写后的吃()
```

这行代码里有个隐式的转换，跟 int 转 double 一样自动，不用写强制。反着来（子类引用接父类对象）就不行了。

向上转型的意义就一个：**统一处理**。一个方法参数写成父类类型，来什么子类都能接：

```java
public static void 喂(动物 a) {   // 参数是动物，狗猫鸟全能传进来
    a.吃();
}
```

不用为每种动物写一个喂的重载，加新动物这方法一行都不用改。

## 动态绑定

`a.吃()` 到底执行谁的方法，编译的时候看的是引用类型（动物，它声明了吃这个方法，编译能过），真正运行的时候 JVM 看的是堆里的实际对象（狗），执行狗的版本——这个运行期才决定调谁的过程就叫动态绑定。

两个推论要记住：

- **编译看左边**：父类引用只能调父类声明过的方法。狗独有的方法，动物引用调不了，编译直接报错
- **运行看右边**：运行时执行的是堆里那个对象（子类）的版本

所以多态下想调子类特有方法，必须先向下转型。

## instanceof 与向下转型

向下转型是显式的强制转换，转错类型运行时直接抛 ClassCastException：

```java
动物 a = new 猫();

狗 d = (狗) a;      // 编译能过（猫和狗都是动物），运行抛 ClassCastException：猫转不成狗
```

所以转之前先 `instanceof` 验一下：

```java
if (a instanceof 狗) {          // 先问一句：你是不是狗
    狗 d = (狗) a;
    d.看家();
}

// 新写法（Java 16+），判断和转型一步到位，推荐
if (a instanceof 猫 m) {
    m.抓老鼠();
}
```

instanceof 的规则：a 是狗的实例、是狗子类的实例都返回 true，但**跟兄弟类比是 false**（猫 instanceof 狗 为 false，这也是为什么上面先判断能防住 ClassCastException）。

## 多态常见的坑

- 属性没有多态！`动物 a = new 狗();` 里访问 a.腿数，用的是**父类**的属性值。多态只发生在方法上（准确说是实例方法），属性和方法是两回事
- static 方法也谈不上多态，它是跟着类走的，引用是什么类型就调谁的版本
- private 方法不能被重写，自然也没有多态

练习里专门验证了属性这条，输出会跟直觉不一样，跑一遍就记住了。
