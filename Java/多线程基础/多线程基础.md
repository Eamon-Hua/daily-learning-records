# Java 多线程基础

记于 2026.11.24

一个进程里同时跑多条执行线路就是多线程。主线程是 main 方法自己，额外开的线程从创建 Thread 开始。

## 三种创建方式

**1. 继承 Thread**：

```java
public class 我的线程 extends Thread {
    @Override
    public void run() {
        System.out.println(getName() + " 在跑");
    }
}
new 我的线程().start();
```

**2. 实现 Runnable**（推荐）：

```java
Runnable 任务 = () -> System.out.println(Thread.currentThread().getName() + " 在跑");
new Thread(任务).start();
```

不占继承名额（Java 单继承，类已经 extends 别的就用不了方式 1），任务和线程分离，一个任务可以交给多个线程。实际写基本都用这个 + lambda。

**3. 实现 Callable**（要返回值时）：

```java
Callable<Integer> 任务 = () -> 1 + 1;
FutureTask<Integer> ft = new FutureTask<>(任务);
new Thread(ft).start();
Integer 结果 = ft.get();    // 阻塞到线程算完
```

三种方式的启动都是 **start()，不是 run()**。直接调 run() 是普通方法调用，当前线程顺序执行完，根本没有第二条线程——这是最常见的错误，看到"多线程没并发"先查这个。start() 只能调一次，第二次抛 IllegalThreadStateException。

## 线程生命周期（6 个状态）

`Thread.getState()` 返回：

| 状态 | 什么时候 |
|---|---|
| NEW | new 出来还没 start |
| RUNNABLE | 可运行（在跑或等着抢 CPU） |
| BLOCKED | 等 synchronized 锁 |
| WAITING | 无限期等：wait()、join()、LockSupport.park() |
| TIMED_WAITING | 限时等：sleep(ms)、wait(ms)、join(ms) |
| TERMINATED | run() 执行完 |

sleep / join 被 interrupt 打断抛 InterruptedException 并清掉打断标记，catch 里要决定继续跑还是退出。

## 常用方法

- **sleep(ms)**：静态方法，让**当前**线程睡。注意它**不释放锁**——抱着 synchronized 的锁睡，别的线程照样进不来
- **join()**：在 A 线程里调 B.join()，A 等到 B 跑完才继续。做"必须等某步完成"的顺序控制
- **setDaemon(true)**：守护线程，必须在 start() 之前设置。所有用户线程结束后 JVM 直接退出，不管守护线程死活。GC 线程就是守护线程。所以守护线程里别做要保证完成的事（写文件写一半 JVM 退出就丢了）
- **currentThread()**：拿到当前正在执行的线程对象，打印日志时常用
- **getName()/setName()**：线程名，默认 "Thread-0" 递增，排查问题时改成有意义的名字

## 线程优先级

优先级 1~10，默认 5，常量 `Thread.MIN_PRIORITY / NORM_PRIORITY / MAX_PRIORITY`：

```java
t.setPriority(Thread.MAX_PRIORITY);   // 10
```

注意两点：

1. **优先级高只是抢到 CPU 的概率高，不是保证**。低优先级线程照样能执行。操作系统对优先级的映射各不相同，别拿优先级做正确性设计——线程间的先后关系用 join / wait / notify 控制，优先级只当性能微调
2. main 线程默认也是 5

线程默认跟着创建它的线程的优先级和守护状态走（子线程继承父线程这些属性）。
