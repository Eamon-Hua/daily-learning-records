# 封装

记于 2026.11.16

封装：**属性用 private 隐藏，对外提供 getter/setter 访问方法**。三个部分：private、getter/setter、构造器里的 this。

## 不封装会怎样

属性直接 public，谁都能改，还能改成不合理的值：

```java
账户 a = new 账户();
a.余额 = -500;   // 没人拦你，余额变负数了
```

所以第一步，把属性用 `private` 隐藏，外面访问不了。

## getter 和 setter

方法命名是固定约定：`getXxx()` 取值、`setXxx()` 改值。setter 里加检查：

```java
class 账户 {
    private double 余额;

    public void set余额(double money) {
        if (money > 0) {        // 校验不通过就不赋值
            this.余额 = money;
        }
    }

    public double get余额() {
        return 余额;
    }
}
```

 IDEA 里可以右键 Generate 一键生成，但手敲几遍记得牢。

## this 是干啥的

构造器参数跟成员变量重名的时候，必须用 `this.` 区分：

```java
public 学生(String name, int age) {
    this.name = name;    // 左边是成员变量，右边是参数
    this.age = age;
}
```

不写 this 就是自己赋值给自己，编译能过但值根本没进去，这个坑非常隐蔽。

## this(...) 调另一个构造器

一个类有多个构造器时，用 `this(...)` 调另一个构造器，公共的初始化逻辑只写一遍：

```java
public 学生(String name, int age) {
    this.name = name;
    this.age = age;
}

public 学生(String name) {
    this(name, 18);      // 默认 18 岁，必须放第一行
}

public 学生() {
    this("无名", 18);
}
```

注意 `this(...)` **必须是构造器第一行**，所以一个构造器里不能又 `this(...)` 又 `super(...)`。

## 封装的固定三步

1. 属性 private
2. 提供 getter/setter，setter 里做检查
3. 构造器里用 this 赋值，有默认值就调 this(...)
