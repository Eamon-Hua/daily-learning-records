# MySQL 触发器

记于 2026.11.19

触发器绑定在表的 INSERT/UPDATE/DELETE 操作上：操作发生时自动执行，不需要手动调用。典型用途：记审计日志、同步冗余字段、拦截不合法数据。

## 创建

四个要素：时机（BEFORE/AFTER）+ 事件（INSERT/UPDATE/DELETE）+ 挂哪张表 + 干什么：

```sql
DELIMITER //

CREATE TRIGGER 记入职日志
AFTER INSERT ON emp        -- 往emp插完数据之后
FOR EACH ROW               -- 固定写法，每受影响的行触发一次
BEGIN
    INSERT INTO emp_log(内容) VALUES(CONCAT('新员工：', NEW.ename));
END //

DELIMITER ;
```

## NEW 和 OLD

触发器里访问行的两套数据：

| 操作 | OLD | NEW |
| :--- | :--- | :--- |
| INSERT | 没有（本来就不存在） | 新插入的那行 |
| UPDATE | 改之前的旧值 | 改之后的新值 |
| DELETE | 被删的那行 | 没有 |

规则：**INSERT 只有 NEW，DELETE 只有 OLD，UPDATE 两个都有**。BEFORE 里还能改 NEW——`SET NEW.salary = 5000;` 可以把即将写入的数据修正；AFTER 里 NEW 已经落库，只能读不能改。

## BEFORE 和 AFTER 的选择

- 要**校验或改写**即将写入的数据 → BEFORE（数据还没落库，可以修改）
- 要**记录已经发生的事**（写日志、扣库存）→ AFTER（确认写进去了再动作）

## 查看、删除

```sql
SHOW TRIGGERS;                     -- 当前库全部触发器
DROP TRIGGER 触发器名;
```

## 两个坑

**触发器不会级联触发**：触发器 A 引发的操作，不会再触发触发器 B，防止循环触发。

**别把业务逻辑堆进去**。触发器是隐形的，排查问题时容易忽略它的存在，一张表挂多个触发器后行为难排查。原则：简单、原子的操作（写一条日志）交给触发器，复杂流程写在应用层或存储过程里。
