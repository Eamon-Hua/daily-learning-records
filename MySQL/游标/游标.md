# MySQL 游标

记于 2026.11.19

游标是给结果集装的一个"指针"：**一行一行往前挪，挪一次取一行**。集合操作（SELECT）是一次性处理整批，游标是逐条处理，适合对每行做不同动作的场景。游标不能单独用，**必须写在存储过程或函数里**。

## 四步走

声明 → 打开 → 取值 → 关闭，顺序固定：

```sql
DELIMITER //

CREATE PROCEDURE 涨薪()
BEGIN
    DECLARE done INT DEFAULT 0;                 -- 1.普通变量先声明
    DECLARE e_name VARCHAR(15);                 -- 2.接数据的变量，类型跟列对上
    DECLARE cur CURSOR FOR SELECT ename FROM emp WHERE salary < 8000;   -- 3.游标绑定查询
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = 1;                -- 4.取完了把done置1

    OPEN cur;                                   -- 打开，此刻才真正执行查询
    读循环: LOOP
        FETCH cur INTO e_name;                  -- 取一行，指针自动后移
        IF done = 1 THEN
            LEAVE 读循环;                        -- 取完了就跳出去
        END IF;
        SELECT e_name;                          -- 拿这行数据干活
    END LOOP;
    CLOSE cur;                                  -- 关闭，释放资源
END //

DELIMITER ;
```

## 三个必踩的坑

**声明顺序不能乱**。BEGIN 后面必须是：普通变量 → 游标 → HANDLER，谁在前谁在后写反了直接语法错误。MySQL 规定的，没商量。

**HANDLER 不写就是死循环**。FETCH 取不到数据时报错，没有 HANDLER 接住，存储过程直接中断；配合 `CONTINUE HANDLER FOR NOT FOUND SET done=1`，取完自动把 done 置 1，循环里判断 done 跳出去，这是标准套路。

**FETCH 一取指针就后移**。没有"往回挪"的操作，想重新过一遍数据只能 CLOSE 再 OPEN。

## 和集合操作的选择

能用 `UPDATE emp SET ... WHERE ...` 一句解决的，别上游标。游标逐行处理性能差一大截，只在"每行的处理逻辑都不一样、一句 SQL 表达不了"时才用。判断标准很简单：先想想能不能写成一句 SQL，能就别用游标。

查看/删除：`SHOW PROCEDURE STATUS WHERE Db='库名'`，`DROP PROCEDURE 名字`。
