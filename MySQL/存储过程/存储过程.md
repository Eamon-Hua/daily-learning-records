# MySQL 存储过程

记于 2026.11.18

存储过程就是**存在数据库里的一段 SQL 集合**，调个名字就整段跑。好处：SQL 不用来回传了、能封装逻辑、跑得快。

## 基本语法

```sql
DELIMITER $$            -- 先把结束符换掉，不然中间的分号会把语句截断

CREATE PROCEDURE 过程名()
BEGIN
    SELECT 1;
    SELECT 2;           -- BEGIN END 里一堆分号也不怕了
END $$

DELIMITER ;             -- 用完记得换回来，不然后面语句全不认

CALL 过程名();          -- 调用
```

DELIMITER 这个坑必踩一次才会：第一次没换结束符，写完 `SELECT 1;` 客户端直接报语法错，整个过程都建不起来。

## 参数三种模式

**IN**：传值进去用，过程里改了也不影响外面（默认就是 IN）。

**OUT**：过程里往里写值，跑完外面能拿到，**当返回值用**。

**INOUT**：既能传进去用，又能带结果出来。

```sql
DELIMITER //

-- IN：只进不出
CREATE PROCEDURE 按部门查人数(IN d INT)
BEGIN
    SELECT COUNT(*) FROM emp WHERE dept_id = d;
END //

-- OUT：传部门号进去，带回总数和平均工资
CREATE PROCEDURE 工资统计(IN 部门 INT, OUT 总数 INT, OUT 平均工资 DOUBLE)
BEGIN
    SELECT COUNT(*), AVG(salary) INTO 总数, 平均工资
    FROM emp WHERE dept_id = 部门;
END //

-- INOUT：进来是多少，出去变成多少
CREATE PROCEDURE 涨薪(INOUT 工资 DOUBLE)
BEGIN
    SET 工资 = 工资 * 1.1;
END //

DELIMITER ;

CALL 按部门查人数(10);

CALL 工资统计(20, @总数, @均薪);    -- OUT 参数要用变量接
SELECT @总数, @均薪;

SET @薪资 = 8000;
CALL 涨薪(@薪资);
SELECT @薪资;                       -- 8800，外面真能拿到
```

## 我踩的坑

- **IN 的形参在过程里改了，外面变量不变**，跟 Java 的值传递一个道理；只有 OUT / INOUT 才回传
- CALL 的时候 OUT 参数**必须给变量**，给个常数直接报错
- 删除是 `DROP PROCEDURE 名字`，注意**没有 IF EXISTS 的分支区分**，过程不叫函数——函数用 `DROP FUNCTION`。查状态用 `SHOW CREATE PROCEDURE 名字`
- 改过程没有 ALTER 改过程体这一说，只能删了重建（ALTER PROCEDURE 只能改名字和权限特性）

## 过程 vs 函数

对比：**过程要 CALL、默认不返回值，适合封装操作步骤；函数嵌在 SQL 里调（SELECT 函数名()），必须有返回值，适合算一个值**。返回多个值、带流程控制就写过程；只要一个计算结果就写函数。
