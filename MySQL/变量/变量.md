# MySQL 变量

记于 2026.11.18

MySQL 里的变量分两大类：**系统变量**和**自定义变量**。自定义的又分两种：@ 开头的用户变量和 DECLARE 的局部变量。

## 系统变量

系统自己维护的，控制服务器行为，比如 `autocommit`、`max_connections`。分**全局 GLOBAL** 和**会话 SESSION** 两种作用域：

```sql
-- 看全部
SHOW GLOBAL VARIABLES;
SHOW SESSION VARIABLES;

-- 看某一个，支持模糊
SHOW VARIABLES LIKE 'autocommit';
SELECT @@global.autocommit;     -- 全局的
SELECT @@session.autocommit;    -- 当前会话的（@@ 默认就是会话级）

-- 改
SET @@global.autocommit = 0;    -- 全局的，新连接才吃到，老连接不受影响
SET @@session.autocommit = 0;   -- 只影响自己这个会话
```

我踩过的坑：改了 GLOBAL 以为立即生效，结果当前会话还是老值——**GLOBAL 只对之后新开的连接生效**，想当场生效得再 SET 一遍 SESSION 级的。

省略级别不写（`SET @@autocommit`）默认是 SESSION。

## 用户变量（@ 开头）

自己定义的，**作用域是当前会话**，断开重连就没了。定义用 `@变量名 := 值` 或 `SET @变量名 = 值`：

```sql
SET @name = '张三';
SELECT @name;                       -- 张三

SELECT @count := COUNT(*) FROM employees;   -- 查询的同时把结果存进变量
SELECT @count;

SELECT salary INTO @avg_sal FROM employees LIMIT 1;  -- INTO 也能存
```

用户变量不用声明类型，类型随赋值而定。局部变量跟它语法相近但规则严格得多，见下。

## 局部变量（DECLARE）

**只能在 BEGIN...END 里用**（存储过程、函数、触发器这些），用之前必须先 DECLARE，带类型，还能给默认值：

```sql
BEGIN
    DECLARE a INT DEFAULT 0;        -- 必须声明，类型必须给
    DECLARE b INT DEFAULT 0;

    SELECT COUNT(*) INTO a FROM employees;
    SET b = a * 10;
    SELECT a, b;
END
```

对比：`@xx` 不用声明、整个会话都能用、会话结束才消失；DECLARE 的必须声明、只活在这个 BEGIN END 里、出了块就没了。**@xx 在普通查询窗口就能定义，DECLARE 的离开存储程序根本没法用。**
