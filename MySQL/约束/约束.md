# MySQL 约束

记于 2026.11.16

约束用于限制表中数据，不合规的数据直接拒绝写入。常用的五个：**主键、非空、唯一、默认、检查**，再加一个管两张表关系的**外键**。

## 主键 PRIMARY KEY

非空 + 唯一，一张表只能有一个主键（可以是多列组合成复合主键）。基本每张表都得有。

```sql
CREATE TABLE t1 (
id INT PRIMARY KEY AUTO_INCREMENT,   -- 自增，不用自己填
name VARCHAR(15) NOT NULL,
phone VARCHAR(20) UNIQUE
);

INSERT INTO t1(name, phone) VALUES('张三', '110');
INSERT INTO t1(name, phone) VALUES('李四', NULL);   -- 不填 id，自增帮你补
```

`AUTO_INCREMENT` 会从上一条 +1 开始，删掉最后一行也**不会**把号 reused，别指望它连续。

## 非空 NOT NULL

不给值直接报错，没什么好说的。

## 唯一 UNIQUE

值不能重复，但**允许多个 NULL**，这个有点反直觉——NULL 在 SQL 里不算"相等"，所以两个 NULL 不算重复。

```sql
INSERT INTO t1(name, phone) VALUES('王五', '110');   -- 报错，110 被张三占了
```

## 检查 CHECK

限定值的范围。注意 **8.0.16 之前 CHECK 只写不查，不生效**，8.0.16 之后才真正生效，用之前先确认版本。

```sql
CREATE TABLE t2 (
age INT CHECK (age > 0 AND age < 150),
gender CHAR(1) DEFAULT '男'
);

INSERT INTO t2(age) VALUES(20);    -- OK，gender 没填，用默认值'男'
INSERT INTO t2(age) VALUES(200);   -- 报错，CHECK 拦住了
```

## 默认值 DEFAULT

不给值就用默认的，跟 CHECK 一样写在列后面。

## 外键 FOREIGN KEY

让从表某一列的值必须在主表里存在，防脏数据：

```sql
CREATE TABLE emp (
empno INT PRIMARY KEY AUTO_INCREMENT,
ename VARCHAR(15),
deptno INT,
CONSTRAINT fk_emp_dept FOREIGN KEY(deptno) REFERENCES dept(deptno)
);

INSERT INTO emp(ename, deptno) VALUES('王五', 30);   -- 报错，部门表里没有 30
DELETE FROM dept WHERE deptno = 10;                  -- 报错，还有员工挂在这个部门
```

两个常见的坑：

- 删主表数据时，从表还有引用就删不掉，除非加级联
- 级联写在约束后面：`ON DELETE CASCADE`（连带删除）或 `ON DELETE SET NULL`（置空）。更新同理 `ON UPDATE CASCADE`

级联危险：删主表一行会连带删除从表多行，生产环境慎用。

## 加约束、删约束

建表时没写，事后用 ALTER 补：

```sql
ALTER TABLE t3 MODIFY id INT PRIMARY KEY;
ALTER TABLE t3 ADD CONSTRAINT uk_email UNIQUE(email);
ALTER TABLE t3 DROP INDEX uk_email;      -- 删唯一约束
ALTER TABLE t3 DROP PRIMARY KEY;         -- 删主键
```
