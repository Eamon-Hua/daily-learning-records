# MySQL 存储函数

记于 2026.11.18

函数与存储过程的核心区别：**函数必须有 RETURNS 返回值，而且能直接嵌在 SQL 里调**（`SELECT 函数名()`），过程只能 CALL。

## 创建函数

比过程多两个地方：括号后面必须声明 RETURNS 类型，函数体里必须有 RETURN：

```sql
DELIMITER //

CREATE FUNCTION 涨后的工资(salary DOUBLE)
RETURNS DOUBLE
DETERMINISTIC
BEGIN
    RETURN salary * 1.1;
END //

DELIMITER ;
```

## DETERMINISTIC 坑

第一次建函数大概率撞这个错：**ERROR 1418，This function has none of DETERMINISTIC, NO SQL, or READS SQL DATA**。

原因：开启二进制日志时，MySQL 要求函数声明自己"是不是确定的"——同样的输入永远给同样的输出就标 `DETERMINISTIC`，不碰数据标 `NO SQL`，只读数据标 `READS SQL DATA`。三种常用标注：

- 纯计算，不看表 → `DETERMINISTIC`
- 函数里 SELECT 了表 → `READS SQL DATA`
- 临时关闭这个检查：`SET GLOBAL log_bin_trust_function_creators = 1;`（重启失效）

## 调用

函数是嵌在 SQL 里用的，不用 CALL：

```sql
SELECT 涨后的工资(5000);                        -- 5500
SELECT ename, salary, 涨后的工资(salary) FROM emp;   -- 每一行都过一遍函数，跟内置函数用法一样
```

这就是函数和过程最直观的差别：函数能出现在 SELECT 的字段列表、WHERE 里，过程做不到。

## 带参的多行函数

```sql
DELIMITER //

CREATE FUNCTION 部门人数(d INT)
RETURNS INT
READS SQL DATA
BEGIN
    DECLARE n INT DEFAULT 0;
    SELECT COUNT(*) INTO n FROM emp WHERE dept_id = d;
    RETURN n;
END //

DELIMITER ;

SELECT 部门人数(10);                       -- 2
SELECT ename, dept_id, 部门人数(dept_id) FROM emp;
```

## 三点对比记忆

| | 存储过程 | 存储函数 |
| :--- | :--- | :--- |
| 返回值 | 可以没有，OUT 参数带回 | 必须 RETURNS + RETURN |
| 调用 | `CALL 名字()` | `SELECT 名字()`，能嵌 SQL |
| 用途 | 干一串活 | 算一个值 |

删除都是 `DROP FUNCTION 名字`，查看 `SHOW CREATE FUNCTION 名字`。
