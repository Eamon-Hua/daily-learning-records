# MySQL 主从复制

记于 2026.11.26

主库写、从库跟着同步，用于读写分离、故障切换和数据备份。

## 复制原理

三个线程，两条线路：

1. 主库 **dump 线程**：从库连接上来后，把 binlog 内容持续推给从库
2. 从库 **IO 线程**：接收 binlog，写入本地的**中继日志（relay log）**
3. 从库 **SQL 线程**：读 relay log，重放里面的变更

流程：主库提交事务写 binlog → dump 推送 → 从库 IO 线程落 relay log → SQL 线程重放。重放方式默认按 ROW 格式逐行应用。

## 两种同步方式

- **异步复制**（默认）：主库写完 binlog 就返回，不等从库确认。主库宕机可能丢还没同步的事务
- **半同步复制**：主库等至少一个从库确认收到 binlog（ACK）才返回客户端。插件：`INSTALL PLUGIN rpl_semi_sync_master SONAME 'semisync_master.so'`。介于异步和全同步之间

## 配置步骤

主库 my.ini / my.cnf：

```ini
[mysqld]
server_id = 1
log_bin = mysql-bin
```

从库：

```ini
[mysqld]
server_id = 2      # 集群内唯一
relay_log = relay-bin
read_only = 1      # 从库只读（super 用户不受限）
```

主库创建复制账号：

```sql
CREATE USER 'repl'@'%' IDENTIFIED BY '复制密码';
GRANT REPLICATION SLAVE ON *.* TO 'repl'@'%';
FLUSH TABLES WITH READ LOCK;                 -- 锁表拿一致性快照
SHOW MASTER STATUS;                          -- 记下 File 和 Position（或用 GTID）
-- mysqldump 全量导出导入到从库
UNLOCK TABLES;
```

从库开启复制（8.0.22+ 语法）：

```sql
CHANGE REPLICATION SOURCE TO
    SOURCE_HOST = '主库IP',
    SOURCE_PORT = 3306,
    SOURCE_USER = 'repl',
    SOURCE_PASSWORD = '复制密码',
    SOURCE_LOG_FILE = 'mysql-bin.000003',   -- SHOW MASTER STATUS 记下的
    SOURCE_LOG_POS = 157;
START REPLICA;
```

老语法 `CHANGE MASTER TO / START SLAVE` 仍兼容。用 GTID 就不用记文件和位置：`SOURCE_AUTO_POSITION = 1`。

## 状态验证

```sql
SHOW REPLICA STATUS\G
```

关键项：

- **Replica_IO_Running / Replica_SQL_Running**：都是 Yes 才是正常复制中
- **Seconds_Behind_Source**：延迟秒数
- **Last_IO_Error / Last_SQL_Error**：报错详情

数据同步验证：主库 `INSERT` 一条测试数据，从库 `SELECT` 确认出现；或在两边分别 `CHECKSUM TABLE 表名` 比对校验值。

## 常见问题

- **从库延迟**：单线程重放大事务追不上。8.0.27+ 有并行复制 `replica_parallel_workers`；业务上拆大事务
- **主键冲突 1062 / 数据不存在 1032**：两边数据分叉后 SQL 线程停了，确认数据来源后 `SET GLOBAL sql_replica_skip_counter = 1; START REPLICA;` 跳过一个事务（谨慎，先搞清楚为什么分叉）
- **read_only 不拦截 super 用户**：从库应用层账号只给 SELECT 权限更可靠
