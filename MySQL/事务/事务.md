# MySQL 事务

记于 2026.11.20

事务就是把几条 SQL 捆成一个整体：**要么全成，要么全不算**。经典场景转账——扣钱和到账两条语句，不能出现扣了钱没到账。

## ACID 四个字母

- **原子性（Atomicity）**：一个事务不可再拆，成是全成，败是全败，靠 undo log 回滚实现
- **一致性（Consistency）**：事务前后数据都处于合法状态，转账总金额不变
- **隔离性（Isolation）**：并发的事务互不干扰，靠锁和 MVCC 实现
- **持久性（Durability）**：COMMIT 之后掉电也不丢，靠 redo log 实现

C 是目的，A/I/D 是手段。

## 基本操作

```sql
START TRANSACTION;            -- 或者 BEGIN
UPDATE account SET money = money - 500 WHERE name = '张三';
UPDATE account SET money = money + 500 WHERE name = '李四';
COMMIT;                       -- 提交，全部生效

-- 中途出问题就
ROLLBACK;                     -- 回滚，这事务里做的全撤销
```

只有 COMMIT 或 ROLLBACK 之间的语句算一个事务。**DDL（CREATE/ALTER）会隐式提交**，事务中间建个表，前面做的全自动提交了，回不去——这是最常踩的坑。

autocommit 默认开着，每条 SQL 自动成为一个事务。显式 START TRANSACTION 后这个开关对当前事务失效。

## 隔离级别与并发问题

并发事务不隔离，会出四种毛病；隔离级别从低到高逐个堵：

| 问题 | 现象 | 堵住它的级别 |
| :--- | :--- | :--- |
| 脏读 | 读到了别人**没提交**的数据，人家回滚你就白读 | READ COMMITTED |
| 不可重复读 | 一个事务里两次读同一行，**值不一样**（别人改了并提交） | REPEATABLE READ |
| 幻读 | 两次读同一范围，**行数不一样**（别人插了并提交） | SERIALIZABLE |
| 丢失更新 | 两边同时改，后提交的覆盖先提交的 | 靠乐观/悲观锁处理 |

四个级别：

- **READ UNCOMMITTED**：啥都不防，脏读都拦不住，基本没人用
- **READ COMMITTED**：只读已提交的，Oracle 默认
- **REPEATABLE READ**：同一事务里重复读结果一致。**MySQL InnoDB 默认**，且靠 MVCC + 间隙锁把幻读也基本堵住了
- **SERIALIZABLE**：串行执行，最安全最慢

```sql
SELECT @@transaction_isolation;                      -- 看当前级别
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;   -- 改当前会话
SET GLOBAL TRANSACTION ISOLATION LEVEL ...;           -- 改全局（新连接生效）
```

## 回滚点

大事务里可以埋存档点，出问题不用全退：

```sql
SAVEPOINT 存档1;
...
ROLLBACK TO 存档1;    -- 只退到这里，之前的操作保留
```
